# MP1 QA 진행 안내

이 폴더는 배포된 MP1 서비스를 직접 테스트하고 결과를 기록하는 곳입니다.

테스트 주소: <https://mp1zero-zero.vercel.app/>

## 파일 역할

| 파일 | 용도 |
| --- | --- |
| `QA_HOW_TO.md` | QA 진행 방법을 먼저 읽는 안내서 |
| `MP1_QA_CHECKLIST.md` | 실제 PASS/FAIL 결과를 기록하는 기본 파일 |
| `QA_ISSUES.md` | FAIL 항목의 증상과 재현 방법을 자세히 적는 파일 |

별도의 결과 파일을 또 만들 필요는 없습니다. **주요 결과는 `MP1_QA_CHECKLIST.md`에 기록**하고, 설명이 긴 오류만 `QA_ISSUES.md`에 추가하면 됩니다.

## 진행 순서

1. `QA_HOW_TO.md`를 읽습니다.
2. `MP1_QA_CHECKLIST.md` 위쪽에 작성자, 배포 주소, 시작 시간을 적습니다.
3. Part A의 MUST 항목부터 차례대로 테스트합니다.
4. Part B의 시니어 사용자 시나리오는 최소 3개 진행합니다.
5. 성공하면 `- [x]`, 실패하면 `- [ ] FAIL: 증상`으로 기록합니다.
6. 실패 원인이 길거나 재현 과정이 필요하면 `QA_ISSUES.md`에 자세히 적습니다.
7. 모든 테스트가 끝난 뒤 종료 시간과 최종 집계를 작성합니다.
8. QA 기록을 커밋한 다음 수정 작업을 시작합니다.

## 직접 기록해야 하는 내용

`MP1_QA_CHECKLIST.md`에 아래 내용을 직접 적어야 합니다.

- 작성자
- 테스트한 Vercel 주소
- 테스트 시작 및 종료 시간
- 각 항목의 PASS/FAIL
- 자격증 선택 테스트에서 사용한 자격증명
- 시니어 시나리오에서 막힌 지점과 읽기 어려웠던 부분
- 전체 PASS/FAIL/미실행 개수

FAIL이 나오면 `QA_ISSUES.md`에 아래 내용도 적습니다.

- 관련 체크 항목 번호
- 사용한 기기와 브라우저
- 오류를 다시 만드는 순서
- 기대한 결과와 실제 결과
- 화면에 나온 오류 문구
- 수정 후 재테스트 결과

## 기록 예시

성공:

```md
- [x] M1. 공개 접수 페이지가 정상적으로 열린다.
```

실패:

```md
- [ ] FAIL: M3. 제출 버튼을 눌러도 완료 화면으로 이동하지 않음
```

## QA 중 주의사항

- 테스트하는 동안에는 코드를 수정하지 않습니다.
- 이름과 연락처는 실제 개인정보가 아닌 테스트 값을 사용합니다.
- API Key, 비밀번호, 실제 연락처는 문서나 화면 캡처에 남기지 않습니다.
- 접수번호가 필요하면 테스트로 만든 접수번호만 기록합니다.
- 한 항목이 실패해도 가능한 다음 항목은 계속 확인합니다.
