## 📌 주요 제약 및 주의사항
1. **정확성 최우선**: 챗봇은 문서에 근거한 내용만 답변해야 하며, 미확인 항목(요양보호사/위생사 수수료 등)이나 문서에 없는 질문은 **"모르겠습니다"**라고 엄격히 답변해야 합니다.
2. **필기 접수 한정**: 본 프로젝트는 실기가 아닌 **필기 시험 접수 및 안내**에 집중합니다.
3. **사용자 친화적 디자인**: 시니어(50~70대) 사용자가 직관적으로 이용할 수 있도록 간결하고 명확한 화면을 구성합니다.

## 🚀 1시간 MVP 실행 방법

우선 자격증은 **한식조리기능사 → 요양보호사 → 공인중개사** 순서로 적용했습니다. 별도 패키지 설치 없이 정적 서버만 실행하면 됩니다.

```bash
python3 -m http.server 4173
```

브라우저에서 아래 주소를 확인합니다.

| 화면 | 로컬 주소 | 구현 기능 |
|---|---|---|
| 접수 페이지 | `http://localhost:4173/` | 자격증 선택, 신청 검증, 접수 저장 |
| FAQ 챗봇 | `http://localhost:4173/chatbot/` | 문서 기반 답변, 유사어, 모름/실기 거절 |
| 통합 어드민 | `http://localhost:4173/admin/` | 접수 통계·검색·상태·CSV, FAQ 수정, 질문 기록 |

자동 테스트는 다음 명령으로 실행합니다.

```bash
node --test tests/chatbot.test.js
```

> 현재 MVP는 브라우저 `localStorage`를 사용합니다. 같은 주소와 브라우저에서는 화면 간 데이터가 연동되지만, 여러 기기에서 함께 운영하려면 다음 단계에서 Supabase 연결이 필요합니다. Vercel에는 저장소 루트를 정적 프로젝트로 한 번 배포하면 위 3개 경로가 함께 배포됩니다.

## 📂 웹 페이지 구조

정적 사이트에서는 폴더별 `index.html`을 두는 방식이 일반적입니다. 작업자는 파일 경로와 실제 URL을 다음처럼 대응해서 보면 됩니다.

```text
index.html             → /
admin/index.html       → /admin/
chatbot/index.html     → /chatbot/
assets/styles.css      → 공통 디자인
js/                    → 공통 데이터·화면 기능
supabase/schema.sql    → DB 테이블과 보안 정책
```

## Supabase 연결

1. Supabase 프로젝트의 SQL Editor에서 `supabase/schema.sql`을 실행합니다.
2. Authentication에서 공개 이메일 회원가입을 끄고 관리자 이메일 계정을 생성합니다.
3. Project Settings > API에서 Project URL과 anon/publishable key를 확인합니다.
4. `js/config.js`의 `SUPABASE_URL`, `SUPABASE_ANON_KEY`에 두 값을 입력합니다.
5. `service_role` 또는 secret key는 브라우저 코드에 절대 넣지 않습니다.

연결 후 공개 사용자는 접수 신청과 질문 등록, FAQ 조회만 할 수 있습니다. 신청자 개인정보 조회·상태 변경·FAQ 수정·질문 기록 조회는 Supabase 관리자 로그인 후에만 가능합니다.

## GitHub와 Vercel 배포

저장소 루트 전체를 GitHub에 올린 뒤 Vercel에서 해당 저장소를 Import합니다. Framework Preset은 `Other`, Root Directory는 `.`로 지정합니다. 배포 후 `/`, `/chatbot/`, `/admin/` 세 주소와 GitHub의 새 커밋이 자동 배포되는지 확인합니다.
